# エラーハンドリング仕様

## 概要

本文書では,艦これ工廠任務廃棄プランナーにおけるエラーハンドリングの方針と具体的な処理を定義する.

## エラー分類

### レベル定義

| レベル   | 説明                         | 影響範囲   | ユーザー操作 | 後続処理                                      |
| :------- | :--------------------------- | :--------- | :----------- | :-------------------------------------------- |
| Critical | アプリの動作が継続不可能     | 全体       | 必須         | 処理を中断,エラー表示後は操作不可または最小限 |
| Error    | 機能の一部が動作不可能       | 特定機能   | 推奨         | 該当機能のみ無効化,他の機能は継続可能         |
| Warning  | 動作は継続可能だが注意が必要 | 特定データ | 任意         | 警告表示のみ,すべての機能は継続可能           |
| Info     | 情報提供のみ(エラーではない) | なし       | 不要         | 通常動作を継続                                |

##### 1.1.1 リトライ・タイムアウト実装詳細

###### リトライロジック

1. GitHub Pagesへの初回アクセス試行
2. 失敗時、1秒待機
3. 1回だけリトライ
4. リトライ失敗時、ローカルフォールバック

###### タイムアウト実装

* `AbortController`を使用してタイムアウト制御
* タイムアウト時間: 10秒
* タイムアウト発生時はエラーとして扱い、リトライまたはフォールバック

###### 実装例

```javascript
async function fetchWithTimeout(url, timeoutMs = 10000) {
  const controller = new AbortController();
  const timeoutId = setTimeout(() => controller.abort(), timeoutMs);

  try {
    const response = await fetch(url, { signal: controller.signal });
    clearTimeout(timeoutId);
    return response;
  } catch (error) {
    clearTimeout(timeoutId);
    if (error.name === 'AbortError') {
      throw new Error('Request timeout');
    }
    throw error;
  }
}

async function fetchWithRetry(url, timeoutMs = 10000) {
  try {
    // 初回試行
    return await fetchWithTimeout(url, timeoutMs);
  } catch (error) {
    console.warn('First attempt failed, retrying after 1 second...');
    // 1秒待機
    await new Promise(resolve => setTimeout(resolve, 1000));
    // リトライ
    return await fetchWithTimeout(url, timeoutMs);
  }
}
```

## エラー回復戦略

### 自動回復

1. **ネットワークエラー**: 自動リトライ(1回)
2. **キャッシュ利用**: フェッチ失敗時にキャッシュフォールバック
3. **部分的動作継続**: 一部のデータ取得失敗でも利用可能な機能は動作

### 手動回復

1. **再試行ボタン**: ネットワークエラー時に再度フェッチ
2. **リロードボタン**: 予期しないエラー時にページリロード
3. **データ修正**: バリデーションエラー時にユーザーが修正

### データ保護

1. **エクスポート推奨**: 容量オーバー前にエクスポートを促す
2. **変更前の確認**: インポート時の上書き警告

## 開発者向けエラーハンドリング

### ロギング

```javascript
// 開発モード: console.error
if (process.env.NODE_ENV === 'development') {
  console.error('[ERROR]', errorMessage, errorDetails);
}

// 本番モード: エラーログ配列に記録
errorLog.push({
  timestamp: new Date().toISOString(),
  level: 'error',
  message: errorMessage,
  details: errorDetails
});
```

### エラー境界(Error Boundary)

* Reactコンポーネントレベルでエラーをキャッチ
* コンポーネント単位でのエラー表示とフォールバックUI

### バリデーション関数

* 入力値のバリデーションは専用関数で集中管理
* エラーメッセージは定数として定義し,一貫性を保つ
