# エラーハンドリング仕様

## 概要

本文書では,艦これ工廠任務廃棄マネージャーにおけるエラーハンドリングの方針と具体的な処理を定義する.

## エラー分類

### レベル定義

| レベル   | 説明                         | 影響範囲   | ユーザー操作 | 後続処理                                      |
| :------- | :--------------------------- | :--------- | :----------- | :-------------------------------------------- |
| Critical | アプリの動作が継続不可能     | 全体       | 必須         | 処理を中断,エラー表示後は操作不可または最小限 |
| Error    | 機能の一部が動作不可能       | 特定機能   | 推奨         | 該当機能のみ無効化,他の機能は継続可能         |
| Warning  | 動作は継続可能だが注意が必要 | 特定データ | 任意         | 警告表示のみ,すべての機能は継続可能           |
| Info     | 情報提供のみ(エラーではない) | なし       | 不要         | 通常動作を継続                                |

## エラーカテゴリ

### 1. データ整合性エラー

#### 1.1 存在しない装備IDの参照

| 項目           | 内容                                                                                                                                                                                                   |
| :------------- | :----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| 発生条件       | 任務の`reqs`内の`id`(要求の対象ID）が装備マスタに存在しない                                                                                                                                            |
| エラーレベル   | Warning                                                                                                                                                                                                |
| 処理フロー     | 1. 該当要求を計算から除外2. 該当任務カードに警告アイコン(⚠️)を表示3. GlobalWarningBannerに表示                                                                                                         |
| 表示メッセージ | 任務カード: ⚠️アイコン(ホバーでツールチップ表示)ツールチップ: `装備ID "m_eq_xxx" が見つかりません`エラーログ: `[任務: 装備の整理] 装備ID "m_eq_xxx" が存在しません. この要求は計算から除外されました.` |
| ユーザー操作   | 任務を編集して正しい装備IDに修正または該当任務を削除                                                                                                                                                   |

#### 1.2 ID重複

| 項目           | 内容                                                                               |
| :------------- | :--------------------------------------------------------------------------------- |
| 発生条件       | 同じIDを持つ装備または任務が複数存在(通常は発生しない)                             |
| エラーレベル   | Warning                                                                            |
| 処理フロー     | 1. 読み込み順で後勝ち(ユーザー定義データが公式マスタより優先)2. エラーログに記録   |
| 表示メッセージ | `⚠️ 重複するID "u_eq_xxx" が検出されました. 最後に読み込まれたデータを使用します.` |

#### 1.3 同一任務内での装備重複要求

| 項目           | 内容                                                                                                                     |
| :------------- | :----------------------------------------------------------------------------------------------------------------------- |
| 発生条件       | 同じ任務の`reqs`配列内で同じ`id`(要求の対象ID）が複数回出現                                                              |
| エラーレベル   | Error                                                                                                                    |
| 処理フロー     | 1. スキーマバリデーション時に検出2. インポート時はエラーとして中断3. 計算時に到達した場合はMAX集計で自動的に最大値を採用 |
| 表示メッセージ | `❌ 任務 "装備の整理" に同じ装備の重複要求があります``装備ID "m_eq_gun_12cm" が2回以上含まれています. 修正してください.` |

### 2. バリデーションエラー

#### 2.1 必須フィールド不足

| 項目           | 内容                                                                                                                     |
| :------------- | :----------------------------------------------------------------------------------------------------------------------- |
| 発生条件       | 装備・任務の作成/編集時に必須フィールドが未入力                                                                          |
| エラーレベル   | Error                                                                                                                    |
| 処理フロー     | 1. 保存ボタンを無効化(Disabled)2. 該当フィールドに赤枠とエラーメッセージを表示                                           |
| 表示メッセージ | 装備名: `装備名は必須です`カテゴリ: `カテゴリは必須です`任務名: `任務名は必須です`要求装備: `要求装備を追加してください` |

#### 2.2 文字数制限超過

| 項目           | 内容                                                                                                             |
| :------------- | :--------------------------------------------------------------------------------------------------------------- |
| 発生条件       | 装備名(40文字),カテゴリ(20文字),任務名(50文字)を超過                                                             |
| エラーレベル   | Error                                                                                                            |
| 処理フロー     | 1. 保存ボタンを無効化(Disabled)2. 該当フィールドに赤枠とエラーメッセージを表示3. 文字数カウンターを表示(`38/40`) |
| 表示メッセージ | `装備名は40文字以内で入力してください (現在: 42文字)`                                                            |

#### 2.3 数値範囲エラー

| 項目           | 内容                                                                                  |
| :------------- | :------------------------------------------------------------------------------------ |
| 発生条件       | 必要数が1未満または30を超過要求装備が10件を超過                                       |
| エラーレベル   | Error                                                                                 |
| 処理フロー     | 1. 保存ボタンを無効化(Disabled)2. 該当フィールドに赤枠とエラーメッセージを表示        |
| 表示メッセージ | 必要数: `必要数は1〜30の範囲で入力してください`要求装備: `要求装備は最大10件までです` |

#### 2.4 同名データの警告

| 項目           | 内容                                                             |
| :------------- | :--------------------------------------------------------------- |
| 発生条件       | 既存の装備・任務と同じ名前を入力                                 |
| エラーレベル   | Warning                                                          |
| 処理フロー     | 1. 保存は可能(ボタンは有効)2. フィールド下に警告メッセージを表示 |
| 表示メッセージ | `⚠️ 同じ名前の装備が既に存在します`                              |

### 3. インポートエラー

#### 3.1 JSON構文エラー

| 項目           | 内容                                                                                                                                                                                                   |
| :------------- | :----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| 発生条件       | アップロードされたファイルが有効なJSON形式ではない                                                                                                                                                     |
| エラーレベル   | Error                                                                                                                                                                                                  |
| 処理フロー     | 1. インポートを中断2. モーダルまたはアラートでエラーを表示                                                                                                                                             |
| 表示メッセージ | `❌ ファイル形式が不正です``有効なJSONファイルを選択してください.``詳細: Unexpected token < in JSON at position 0`                                                                                     |
| 後続処理       | インポート処理は完全に中断される. 既存データは一切変更されない. モーダル/アラートを閉じるとインポート前の状態に復帰し,通常の操作が可能. ユーザーは正しいファイルを選択し直してインポートを再試行できる |

#### 3.2 スキーマ不一致

| 項目           | 内容                                                                                                                                                                                                                                                  |
| :------------- | :---------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| 発生条件       | 必須フィールドが存在しないフィールドの型が異なるID形式が不正                                                                                                                                                                                          |
| エラーレベル   | Error                                                                                                                                                                                                                                                 |
| 処理フロー     | 1. インポートを中断2. 詳細なエラーメッセージを表示                                                                                                                                                                                                    |
| 表示メッセージ | `❌ データ形式が不正です``以下の問題を修正してください:``• equipments[0].name: 必須フィールドが存在しません``• missions[1].reqs[0].count: 数値型である必要があります (現在: "3")``• equipments[2].id: ID形式が不正です (u_eq_で始まる必要があります)` |
| 後続処理       | インポート処理は完全に中断される. 既存データは変更されず保持される. ユーザーはデータファイルを修正して再度インポートする必要がある                                                                                                                    |

#### 3.3 ファイル判別失敗

| 項目           | 内容                                                                                                                                                          |
| :------------- | :------------------------------------------------------------------------------------------------------------------------------------------------------------ |
| 発生条件       | `equipments`配列も`missions`配列も存在しない、または両方とも存在する                                                                                          |
| エラーレベル   | Error                                                                                                                                                         |
| 処理フロー     | 1. インポートを中断2. エラーメッセージを表示                                                                                                                  |
| 表示メッセージ | 両方なし: `❌ データ形式を判別できません``装備データ (equipments) または任務データ (missions) が含まれていません.`両方あり: `❌ 統合ファイルは非サポートです` |
| 後続処理       | インポート処理は完全に中断される. 既存データは変更されず保持される. ユーザーは正しい形式のファイルを選択し直す必要がある                                      |

### 4. LocalStorage/SessionStorageエラー

#### 4.1 容量オーバー

| 項目           | 内容                                                                                                                                                                                                                                             |
| :------------- | :----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| 発生条件       | LocalStorageの容量制限(通常5〜10MB)を超過QuotaExceededError                                                                                                                                                                                      |
| エラーレベル   | Error                                                                                                                                                                                                                                            |
| 処理フロー     | 1. 保存を中断2. アラートで通知3. データ削減の提案を表示                                                                                                                                                                                          |
| 表示メッセージ | `❌ データの保存に失敗しました``ブラウザの保存容量が不足しています.``以下の対応を検討してください:``• 不要な装備・任務を削除する``• データをエクスポートして別途保管する``• ブラウザのキャッシュをクリアする`                                    |
| ユーザー操作   | [データをエクスポート]ボタン: 現在のデータをダウンロード[閉じる]ボタン: アラートを閉じる                                                                                                                                                         |
| 後続処理       | 保存処理は中断され,最新の変更は保存されない(ページを閉じると失われる). 既存の保存済みデータは保持される. アラートを閉じた後も閲覧・計算は可能だが,追加の編集操作は避けるべき. ユーザーはデータを削減またはエクスポートしてから再度保存操作を行う |

#### 4.2 プライベートモード制限

| 項目           | 内容                                                                                                                                                                                                                                                      |
| :------------- | :-------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| 発生条件       | プライベート/シークレットモードでLocalStorageが無効                                                                                                                                                                                                       |
| エラーレベル   | Warning                                                                                                                                                                                                                                                   |
| 処理フロー     | 1. アプリ起動時に検出2. 警告バナーを表示3. 読み取り専用モードで起動                                                                                                                                                                                       |
| 表示メッセージ | `⚠️ プライベートモードで動作しています``データの保存ができません. 公式マスタデータとインポートしたデータのみで動作します.`                                                                                                                                |
| 後続処理       | アプリは読み取り専用モードで起動する. 公式マスタデータの取得とファイルからのインポートは可能. 計算機能も利用可能. ただしユーザー定義データの作成・編集・保存は不可. 装備・任務の追加/編集UIは無効化される. ページを閉じるとインポートしたデータは失われる |

#### 4.3 他タブでのデータ更新

| 項目           | 内容                                                                                                             |
| :------------- | :--------------------------------------------------------------------------------------------------------------- |
| 発生条件       | 別のタブでLocalStorageが更新された(`storage`イベント)                                                            |
| エラーレベル   | Warning                                                                                                          |
| 処理フロー     | 1. 通知バナーを画面上部に表示2. 自動リロードは行わない                                                           |
| 表示メッセージ | `ℹ️ 別のタブでデータが更新されました``最新のデータを読み込むにはページをリロードしてください.``[リロード]ボタン` |

#### 4.4 起動時データ破損検出

| 項目           | 内容                                                                                                                                                                                                                                                                                                                                                    |
| :------------- | :------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------ |
| 発生条件       | アプリ起動時にLocalStorageから読み込んだユーザー定義データ(装備・任務)がスキーマバリデーションに失敗必須フィールド不足、ID形式不正、型不一致、同一任務内装備重複など                                                                                                                                                                                    |
| エラーレベル   | Warning                                                                                                                                                                                                                                                                                                                                                 |
| 処理フロー     | 1. `src/store/storage.ts` の `loadUserCategories()` / `loadUserEquipments()` / `loadUserMissions()` で全データをバリデーション2. 破損データを特定し、配列から除外3. 正常なデータのみでLocalStorageを上書き保存4. 削除されたデータの詳細をグローバル警告バナーに表示5. アプリは正常なデータのみで起動                                                    |
| 表示メッセージ | `⚠️ データ整合性の問題を検出しました``以下のデータを自動的に削除しました:``• 装備 "test装備": ID形式が不正です (u_eq_で始まる必要があります)``• 任務 "テスト任務": 必須フィールド period が存在しません``正常なデータのみで動作しています.`                                                                                                             |
| ユーザー操作   | バナーの[×]ボタン: 通知を非表示にする                                                                                                                                                                                                                                                                                                                   |
| 後続処理       | 破損データは完全に削除され、復元不可能. 正常なデータは保持され、すべての機能が通常通り利用可能. ユーザーは必要に応じて削除されたデータを手動で再作成する必要がある. LocalStorage直接編集やブラウザ拡張機能による破損から自動的に回復し、アプリの動作を安定させる                                                                                        |
| 実装の意図     | LocalStorageの直接編集、ブラウザ拡張機能による改変、古いバージョンのアプリで作成されたデータなど、稀なケースで発生するデータ破損に対する防御策. 保存時バリデーションで予防できない外部要因による破損を起動時に検出し、自動修復することでアプリの安定性を保証する. import機能(#12)とは異なり、起動時の自動処理のため、ユーザーの操作を妨げない設計とする |

## エラー表示UI

### グローバル警告バナー (GlobalWarningBanner)

- 位置: 画面最上部(Header直下)
- 管理: Zustand store (`dataWarnings`) 経由でエラーを取得・表示
- スタイル:
    - 背景色: 濃い赤(Critical), 赤(Error), 黄色(Warning), 青色(Info)
    - アイコン: AlertCircle
    - 閉じるボタン: Critical以外で表示

#### エラーレベルと挙動

| レベル       | ユーザー操作 (Dismiss) | 想定ケース                                   | 表示スタイル                |
| :----------- | :--------------------- | :------------------------------------------- | :-------------------------- |
| **CRITICAL** | **不可**               | アプリ継続不能な例外, 致命的な不整合         | 濃い赤色 / 閉じるボタンなし |
| **ERROR**    | **可**                 | 保存失敗, CRUD操作エラー, インポート失敗     | 赤色 / 閉じるボタンあり     |
| **WARNING**  | **可**                 | 破損データの自動削除通知, 軽微な整合性エラー | 黄色 / 閉じるボタンあり     |
| **INFO**     | **可**                 | Beta版通知, 成功メッセージ等                 | 青色 / 閉じるボタンあり     |

**注**: CRITICALタイプは将来拡張用として定義済み. 現時点では使用箇所なし.

#### エラータグと表示バナー

| タグ                 | 表示内容                          | バナータイプ |
| :------------------- | :-------------------------------- | :----------- |
| corrupted-equipments | 破損装備データの自動削除通知      | warning      |
| corrupted-missions   | 破損任務データの自動削除通知      | warning      |
| alpha-info           | Beta版の注意事項                  | info         |
| equipment-crud-error | 装備CRUD操作のエラー              | error        |
| mission-crud-error   | 任務CRUD操作のエラー              | error        |
| destructive-op-error | 破壊的操作(削除/リセット)のエラー | error        |

### 任務カード警告アイコン

- 位置: 任務カードの右上
- スタイル:
    - アイコン: ⚠️(黄色)
    - ホバーでツールチップ表示
- 表示条件:
    - 存在しない装備IDを参照

### モーダルエラー

- 使用ケース:
    - インポートエラー
    - 保存失敗
    - 予期しないエラー
- スタイル:
    - モーダルオーバーレイ
    - 中央表示
    - アイコン + メッセージ + ボタン

## エラー回復戦略

### 自動回復

1. **起動時データ破損検出**: LocalStorageの破損データを自動削除
1. **部分的動作継続**: 一部のデータに問題があっても利用可能な機能は動作

### 手動回復

1. **リロードボタン**: 予期しないエラー時にページリロード
1. **データ修正**: バリデーションエラー時にユーザーが修正

### データ保護

1. **エクスポート推奨**: 容量オーバー前にエクスポートを促す
1. **変更前の確認**: インポート時の上書き警告
1. **バージョン管理**: 互換性のないデータは拒否

## 開発者向けエラーハンドリング

### ロギング

```typescript
// 開発モード: console.error (Vite環境変数)
if (import.meta.env.DEV) {
    console.error('[ERROR]', errorMessage, errorDetails);
}
```

### エラー境界(Error Boundary)

- Reactコンポーネントレベルでエラーをキャッチ
- コンポーネント単位でのエラー表示とフォールバックUI

### バリデーション

- 入力値のバリデーションは `src/schema/` のZodスキーマで集中管理
- フォームバリデーションは react-hook-form + `@hookform/resolvers/zod` で宣言的に処理
- 起動時のLocalStorageデータバリデーションは `src/store/storage.ts` で実行
