# v2.0.0 ロードマップ

最終更新: 2025-12-09

## 概要

v2.0.0では、v1.0.0-betaリリース後に明確になったユースケースの改善と、データ構造の根本的な見直し、およびアーキテクチャの刷新を行う。これにより、より柔軟で保守性の高いアプリケーションを実現する。

## v2.0.0リリース戦略

```
v1.0.0-beta (完了)
  ↓
Phase 1-3: コア機能実装 (完了)
  ↓
v2.0.0-alpha リリース ← 現在地
  ↓
Phase 4: リファクタリング (実施中)
  ↓
v2.0.0 正式版リリース
```

**戦略**:

1. **v2.0.0-alpha**: Phase 1-3のコア機能（データ構造改善、計算ロジック拡張、UX改善）を含む早期リリース
2. **Phase 4実施**: アーキテクチャ刷新とリファクタリングを段階的に実施
3. **v2.0.0正式版**: 全リファクタ完了後にalphaタグを解除

**メリット**:

* ユーザーへの早期価値提供（コア機能を先行リリース）
* リファクタリングを段階的に実施し、リスク分散
* alphaタグで「開発中」を明示しつつ、実際に使用可能な状態を提供

## Phase 1-3: コア機能（完了）

### Phase 1: データ構造改善（完了 2025-12-03）

**実施内容**:

* #74: カテゴリ代表装備の動的生成によるデータ整合性の改善
* #80: データ変換層の導入によるコード責務の明確化
* #83: App.jxのビジネスロジックをドメイン層に分離
* #89: ID Map生成ユーティリティの作成
* #90: useSelectedMissionsのロジック簡素化
* #91: 小規模リファクタリングの実施（useToggle, WarningCollector, フィルタ統合）
* #97: 装備管理リストのアコーディオン化による操作性改善と並び替えバグ修正

**効果**:

* データ整合性の構造的保証
* コードの責務分離と保守性向上
* 約150行のコード削減

### Phase 2: 計算ロジック拡張（完了 2025-12-04）

**実施内容**:

* #75: 任務の実行回数選択を可能にする
  * 選択中任務のデータ形式変更（`string[]` → `{missionId, count}[]`）
  * 実行回数選択UI追加（1〜99回）
  * 実行回数を考慮した廃棄数計算

**効果**:

* 複数回実行による大量廃棄の達成を支援
* ユースケースの拡大

### Phase 3: UX改善（完了 2025-12-05）

**実施内容**:

* #76: 任務選択をベース任務と補助任務に分ける
  * データ形式変更（`{baseMission, auxiliaryMissions}`）
  * ベース任務と補助任務の明確な分離
  * 過不足比較機能の実装
  * StickyDashboard内でのベース任務達成状況表示

**効果**:

* 「特定任務をクリアしたい + 並列で実行できる任務を探す」というユースケースに対応
* 視覚的な過不足表示により、廃棄計画の最適化が容易に
