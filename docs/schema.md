# データスキーマ仕様

## 概要

本文書では,艦これ工廠任務廃棄プランナーで使用する全データ構造を定義する.マスタデータ(GitHub Pages配信)とエクスポート/インポートで使用するJSON形式は共通の構造を持つ.

## バージョニング

全JSONファイルは`version`フィールドを持ち,Semantic Versioning (vX.Y.Z) に従う.

* **Major (X)**: スキーマ構造の非互換変更(フィールドの削除,型変更など)
* **Minor (Y)**: 後方互換性のある追加(新規フィールド,データ追加)
* **Patch (Z)**: データ修正(誤字訂正,バグ修正)

現在のスキーマバージョン: `1.0.0`

## ID規則

データの競合を防ぐため,IDにはプレフィックスによる名前空間を使用する.

| データ種別   | プレフィックス | フォーマット例       | 生成方法              | 削除可否 |
| :----------- | :------------- | :------------------- | :-------------------- | :------- |
| 公式装備     | `m_eq_`        | `m_eq_gun_12cm`      | 手動定義              | 不可     |
| 公式任務     | `m_ms_`        | `m_ms_daily_scrap_1` | 手動定義              | 不可     |
| ユーザー装備 | `u_eq_`        | `u_eq_<UUID>`        | `crypto.randomUUID()` | 可       |
| ユーザー任務 | `u_ms_`        | `u_ms_<UUID>`        | `crypto.randomUUID()` | 可       |

### ID生成ルール

* 公式マスタのIDは英数字とアンダースコアのみ使用し,可読性を重視する
* ユーザー定義データのIDはUUID v4を使用し,衝突を回避する
* IDは一度発行したら変更不可(参照整合性の維持のため)

## データ構造定義

### 1. 装備マスタデータ (equipments.json)

```json
{
  "version": "1.0.0",
  "equipments": [
    {
      "id": "m_eq_gun_12cm",
      "name": "12cm単装砲",
      "category": "小口径主砲",
      "type": "Item"
    },
    {
      "id": "m_eq_cat_main_gun_s",
      "name": "小口径主砲",
      "category": "小口径主砲",
      "type": "Category"
    }
  ]
}
```

#### フィールド定義

| フィールド   | 型     | 必須 | 説明               |
| :----------- | :----- | :--- | :----------------- |
| `version`    | String | ○    | スキーマバージョン |
| `equipments` | Array  | ○    | 装備データの配列   |

#### Equipment オブジェクト

| フィールド | 型     | 必須 | 制約                     | 説明                                         |
| :--------- | :----- | :--- | :----------------------- | :------------------------------------------- |
| `id`       | String | ○    | ID規則に従う             | 一意識別子                                   |
| `name`     | String | ○    | 1〜40文字                | 装備名                                       |
| `category` | String | ○    | 1〜20文字                | カテゴリ名(集計キー)                         |
| `type`     | Enum   | ○    | `"Item"` or `"Category"` | 具体装備(`Item`) or カテゴリ代表(`Category`) |

#### type の使い分け

* `Item`: 具体的な装備(例: "12cm単装砲", "25mm単装機銃")
* `Category`: カテゴリを代表するエントリ(例: "小口径主砲", "機銃")
    * 任務の要求装備で「機銃×3」のようにカテゴリ指定する場合に使用
    * `name`と`category`は通常同じ値

### 2. 任務マスタデータ (missions.json)

```json
{
  "version": "1.0.0",
  "missions": [
    {
      "id": "m_ms_daily_scrap_1",
      "name": "装備の整理",
      "period": "Daily",
      "reqs": [
        {
          "id": "req_1",
          "targetId": "m_eq_cat_main_gun_s",
          "count": 2
        },
        {
          "id": "req_2",
          "targetId": "m_eq_gun_12cm",
          "count": 1
        }
      ]
    }
  ]
}
```

#### ルート要素

| フィールド | 型     | 必須 | 説明               |
| :--------- | :----- | :--- | :----------------- |
| `version`  | String | ○    | スキーマバージョン |
| `missions` | Array  | ○    | 任務データの配列   |

#### Mission オブジェクト

| フィールド | 型     | 必須 | 制約         | 説明             |
| :--------- | :----- | :--- | :----------- | :--------------- |
| `id`       | String | ○    | ID規則に従う | 一意識別子       |
| `name`     | String | ○    | 1〜50文字    | 任務名           |
| `period`   | Enum   | ○    | 下記参照     | 任務の周期       |
| `reqs`     | Array  | ○    | 1〜10件      | 要求装備のリスト |

#### period の値

| 値          | 説明         |
| :---------- | :----------- |
| `Daily`     | デイリー     |
| `Weekly`    | ウィークリー |
| `Monthly`   | マンスリー   |
| `Quarterly` | クォータリー |
| `OneTime`   | 単発         |

#### Requirement オブジェクト

| フィールド | 型     | 必須 | 制約             | 説明                                  |
| :--------- | :----- | :--- | :--------------- | :------------------------------------ |
| `id`       | String | ○    | 同一任務内で一意 | 要求装備の識別子(UI表示順序の保持用)  |
| `targetId` | String | ○    | 装備IDに対応     | 要求する装備のID(`equipments.json`内) |
| `count`    | Number | ○    | 1〜20の整数      | 必要数                                |

#### 注意事項

* `reqs`配列内で同じ`targetId`が複数回出現してはならない(同じ装備を複数回要求する場合は`count`を加算する)
* `targetId`が存在しない装備IDを参照している場合,計算時に警告を表示し,その要求は無視される

### 3. ユーザーデータ (LocalStorage)

ブラウザの`localStorage`に保存されるデータ構造を定義する.

#### 3.1 キー一覧

| キー名                  | 内容                   | データ型   | 永続化         |
| :---------------------- | :--------------------- | :--------- | :------------- |
| `ksp_app_version`       | アプリバージョン       | String     | LocalStorage   |
| `ksp_user_equipments`   | ユーザー定義装備リスト | JSON文字列 | LocalStorage   |
| `ksp_user_missions`     | ユーザー定義任務リスト | JSON文字列 | LocalStorage   |
| `ksp_selected_missions` | 選択中の任務IDリスト   | JSON文字列 | SessionStorage |

#### 3.2 ksp_user_equipments

| `selectedMissionIds` | Array  | ○    | 最大8件 | 選択中の任務IDリスト |

### 4. エクスポート/インポートデータ

ユーザー定義データをエクスポート/インポートする際のJSON形式を定義する.装備と任務でファイルを分割し,マスタデータと同じ構造を使用する.

#### 4.1 装備エクスポートデータ (user_equipments.json)

```json
{
  "version": "1.0.0",
  "equipments": [
    {
      "id": "u_eq_123e4567-e89b-12d3-a456-426614174000",
      "name": "カスタム砲",
      "category": "主砲",
      "type": "Item"
    }
  ]
}
```

構造は`equipments.json`と同一.

#### 4.2 任務エクスポートデータ (user_missions.json)

```json
{
  "version": "1.0.0",
  "missions": [
    {
      "id": "u_ms_123e4567-e89b-12d3-a456-426614174001",
      "name": "カスタム任務",
      "period": "Weekly",
      "reqs": [
        {
          "id": "req_1",
          "targetId": "m_eq_gun_12cm",
          "count": 3
        }
      ]
    }
  ]
}
```

構造は`missions.json`と同一.

#### 4.3 エクスポート/インポートの仕様

* **エクスポート**: 装備と任務を別々のファイルとしてダウンロード
    * ファイル名: `kancolle_scrap_equipments_YYYYMMDD.json`, `kancolle_scrap_missions_YYYYMMDD.json`
* **インポート**: 装備または任務のファイルを個別に読み込み可能
    * ファイルの`version`フィールドで装備/任務を自動判別
    * 装備ファイル: `equipments`配列が存在
    * 任務ファイル: `missions`配列が存在
* **上書き挙動**: インポート時は該当タイプの既存データを全上書き(事前警告あり)
* **部分インポート**: 装備のみ,任務のみのインポートが可能

## バリデーション規則

### インポート時のバリデーション

1. **JSON構文チェック**: 有効なJSON形式か
2. **必須フィールドチェック**: 上記の必須フィールドが全て存在するか
3. **型チェック**: 各フィールドの型が正しいか
4. **ID形式チェック**: IDのプレフィックスが規則に従っているか
5. **UUID検証**: ユーザー定義データのIDがUUID v4形式か(正規表現: `/^[0-9a-f]{8}-[0-9a-f]{4}-4[0-9a-f]{3}-[89ab][0-9a-f]{3}-[0-9a-f]{12}$/i`)
6. **文字数制限チェック**: 各フィールドの文字数が制限内か
7. **数値範囲チェック**: `count`が1〜20の範囲内か
8. **配列長チェック**: `reqs`が1〜10件の範囲内か
9. **参照整合性チェック**: `targetId`が装備マスタに存在するか(警告レベル,インポートは継続)
10. **重複チェック**: 同一ID, 同一名称の重複がないか(警告レベル)

### バリデーションエラー時の挙動

* **エラー(Critical)**: インポートを中断し,エラーメッセージを表示
    * 対象: 1〜8
* **警告(Warning)**: インポートは継続するが,警告を表示
    * 対象: 9, 10

## データマイグレーション

### バージョン互換性判定

アプリ起動時,以下の順序でバージョンをチェックする.

1. `LocalStorage`の各データの`version`フィールドを読み取る
2. 現在のアプリがサポートする`schemaVersion`と比較
3. 判定結果に応じて処理を分岐

| 条件                            | 挙動                                                                                   |
| :------------------------------ | :------------------------------------------------------------------------------------- |
| `version` = サポートバージョン  | そのまま読み込み                                                                       |
| `version` < サポートバージョン  | マイグレーション処理を実行(将来実装)                                                   |
| `version` > サポートバージョン  | エラー表示「新しいバージョンでエクスポートされたデータです. アプリを更新してください」 |
| `version`フィールドが存在しない | エラー表示「不正なデータ形式です」                                                     |

### マイグレーション戦略 (将来実装)

* 初期リリース(v1.0.0)ではマイグレーション機能は未実装
* Major版更新時はマイグレーションツールの提供を検討
* Minor/Patch版では後方互換性を維持し,マイグレーション不要とする
